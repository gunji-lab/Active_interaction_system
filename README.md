# 講義レスポンス

大学の講義向けの匿名回答アプリです。GitHub Pages に画面を置き、認証と回答保存に Supabase を使います。教員は講義と複数の大問を作成し、各大問に「問1・問2・問3」のような小問を最大12個まで追加できます。学生はQRコードから参加し、表示中の大問の小問をまとめて回答します。

## できること

- 小問ごとに選択式・数値・自由記述を選び、正解と解説を設定
- 教員: メールとパスワードでログイン、講義・問題の作成、回答を約3秒ごとに確認
- 学生: アカウント不要。各大問について、すべての小問に回答して1回送信
- 公開操作: `受付開始` → `受付終了` → `回答分布・一覧を公開` → `正解・解説を公開`。公開は大問単位で行い、集計は小問ごとに表示
- 「準備中に戻す」で学生画面から問題を外せます。回答がある場合は保存か削除を選べます。保存した問題は回答との対応を守るため編集できません。削除すると同じ学生も再回答できます。
- 同じブラウザの同じ端末からは、各大問につき最初の回答だけを保存
- 数値は全角数字、全角小数点・符号、桁区切りカンマ、指数表記（例 `1.5e-3`）を受け付け、集計時に同じ値へ正規化

## すでにSupabaseで旧版のSQLを実行した場合

小問対応版を公開する**前に**、Supabase の **SQL Editor** で [`supabase/upgrade_subquestions.sql`](supabase/upgrade_subquestions.sql) を実行してください。既存の講義、問題、回答は残ります。実行結果が `Success. No rows returned` なら完了です。旧版の単問は「小問1つ」として引き続き表示されます。回答がある問題の小問構成を後から変えないよう、アプリでは出題済みの問題の編集を止めています。

「準備中に戻す」を追加するには、続けて [`supabase/upgrade_reset_to_draft.sql`](supabase/upgrade_reset_to_draft.sql) を SQL Editor で実行してください。このSQLだけでは回答は削除されません。

## 新しいSupabaseプロジェクトで始める場合

1. [Supabase](https://supabase.com/) でプロジェクトを作る。
2. **SQL Editor** で [`supabase/schema.sql`](supabase/schema.sql) を実行する。旧版のSQLを実行したプロジェクトには上記の更新用SQLを使う。
3. **Authentication → Users → Add user → Create new user** から教員アカウントを作成する。メールとパスワードを設定し、必要ならメールを確認済みにする。一般向けの新規登録は無効にしておく。アプリに新規登録画面はありません。
4. **Connect** から `Project URL`（`https://...supabase.co`）と `Publishable key`（`sb_publishable_...`）を控える。`/rest/v1/` 付きの Data API URL は使わない。`Secret` / `service_role` キーは画面や GitHub に入れない。

SQL は教員本人だけに自分の講義・問題・回答への直接アクセスを許可します。学生は制限した関数だけを使い、回答公開前の集計や正解を取得できません。

## GitHub Pages に公開

1. リポジトリの **Settings → Secrets and variables → Actions → Variables** に `VITE_SUPABASE_URL` と `VITE_SUPABASE_ANON_KEY` を登録する。後者には Publishable key を入れる。これらは公開可能な値で、サイトのコードに含まれます。
2. **Settings → Pages → Source** を **GitHub Actions** にする。
3. `.github/workflows/deploy.yml` が `main` への push 時にサイトを公開します。GitHub の **Actions** で `Deploy Pages` が成功したことを確認する。
4. 公開サイトに `?teacher=1` を付けると教員画面です。講義を作成すると参加URLとQRコードが表示されます。

Cloudflare Pages でも、ビルドコマンド `npm run build`、出力ディレクトリ `dist`、同じ2つの環境変数で公開できます。

## ローカルで動かす

Node.js 20 以上を用意します。

```sh
npm ci
cp .env.example .env
```

`.env` に Project URL と Publishable key を設定し、`npm run dev` で起動します。`npm run build` で型検査と本番ビルドを行います。

## 授業での使い方

1. 教員画面で講義を作り、大問の文を入力して小問を追加します。各小問の形式、選択肢、正解、解説を設定します。図は授業のスライドで見せます。
2. 学生にQRコードまたは参加URLを共有し、「この問題を出題・受付開始」を押します。学生はすべての小問を埋めて一度に送信します。
3. 教員画面で小問ごとの回答と件数を確認します。「受付終了」の後、「回答分布・一覧を公開」と「正解・解説を公開」を別々に操作します。
4. 次の大問を選んで出題します。前の回答は教員画面に残ります。

## 運用上の範囲

- ブラウザの保存データを消す、別端末を使うなどすれば再回答できるため、厳格な本人確認や採点には適しません。
- 回答一覧を公開すると自由記述の原文も全員に見えます。個人情報を書かないよう学生に案内してください。
- 大規模授業では約3秒ごとの確認が Supabase の利用量を増やします。必要なら間隔や利用プランを調整してください。
- 以前の画像アップロード版で設定済みの場合、画像保存用バケットと既存画像は自動削除しません。不要なら Supabase の Storage 画面で確認して削除してください。
